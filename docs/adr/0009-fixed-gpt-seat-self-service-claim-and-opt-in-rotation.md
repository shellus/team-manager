# 固定 GPT 席位使用待认领资源和显式授权换号

## 状态

已接受，2026-08-24；尚未实施。

## 背景

固定席位空位是订阅权益容量减去远端成员和邀请占用后的实时投影，没有稳定身份，不能直接绑定公开 URL。业务需要在租客尚未提供邮箱时先预留一个可管理位置并发送稳定 URL，由租客完成第一次邀请；同一 URL 还需要按席位级配置支持后续换号和待接入的数据导出。

公开换号自动移除已接受的固定 ChatGPT 成员可能造成旧席位继续临时计费、新邀请产生新增费用、旧账号立即失去 Workspace 访问和凭证失效。完全禁止可以降低风险，但无法满足管理员明确授权客户自助轮转的业务需求。

## 决策

- 固定席位空位继续保持实时投影；只有管理员显式预留时才创建没有当前邮箱、具有稳定 `seatKey` 的待认领 `SeatSlot`。
- 待认领席位只用于 `default` 固定 GPT 席位，减少本地可分配固定席位余量但不计入远端 `fixedSeatOccupied`。
- 公开 URL 本身授权首次认领。首次认领不设开关，提交首个邮箱并成功创建邀请后立即开始默认 7 天的换号冷却期。
- 后续公开换号与数据导出分别使用席位级开关，现有和新建客户席位都默认关闭。换号开关只控制首次认领后的邮箱变更。
- 管理员显式开启后续换号时，公开流程可以自动移除已接受的固定 ChatGPT 成员并邀请新邮箱；这一点部分取代 [ADR 0002](./0002-block-standard-seat-public-rotation.md) 的绝对禁止规则。默认关闭、计费风险提示、冷却期、单席位并发锁、完整操作步骤和上游 Billing 风险证据必须同时保留。
- 数据导出由后续提供的上游管理员接口实现。公开页面只访问 Team Manager 受控后端，管理员接口凭证不得进入浏览器；没有当前邮箱的待认领席位不能导出。

## 后果

`SeatSlot` 不再等同于已经绑定邮箱的租客资料，而是可以先表达一个已预留、待认领的客户资源。容量空位、待认领席位、远端固定席位占用和账单数量继续保持独立语义。历史公开 URL 不会因上线新字段自动获得移除正式成员的权限；管理员必须逐席位开启后续换号并接受计费与访问风险。
