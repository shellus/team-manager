# 固定 GPT 席位自助管理计划

状态：需求已确认，尚未实施。数据导出等待上游管理员接口样本。

## 目标

为固定 GPT 席位建立从“管理员预留空位、租客首次认领、后续按配置换号”到未来数据导出的稳定公开自助流程。公开 URL 在租客提供邮箱前即可生成；首次认领默认允许，后续换号和数据导出必须逐席位显式开启。

## 范围

- 包含：固定 `default` ChatGPT 席位的待认领资源、成员 Tab 管理入口、公开首次邀请、后续换号权限和冷却、导出权限占位、审计和计费风险保护。
- 不包含：Codex/`usage_based` 席位、自动物化全部容量空位、未经确认的上游数据导出协议、源码或生产数据变更。

## 已确认术语与状态

| 对象或状态 | 含义 | 是否占用远端固定席位 |
|------|------|------|
| 固定席位空位 | `fixedSeatCapacity - fixedSeatOccupied` 的实时查询投影 | 否 |
| 待认领席位 | 管理员从已知空位显式预留、已有 `seatKey` 但尚无邮箱的 `SeatSlot` | 否 |
| 邀请中 | 租客首次认领或换号后已经创建 `default` 邀请 | 是 |
| 已加入 | 邮箱已经成为活动 `default` 成员 | 是 |

本地可分配固定席位余量等于固定席位空位减去待认领席位数量。待认领席位不得覆盖 `fixedSeatOccupied`、`subscriptionSeatsInUse` 或 `billedSeatQuantity`。

## 产品规则

### 管理入口

- 成员 Tab 工具栏提供“创建待认领席位”，只允许从容量已知且仍有本地可分配余量的固定 GPT Workspace 创建。
- 创建后，成员表出现“待认领”行；“成员”字段显示“复制自助管理链接”按钮，复制 `/seat/:seatKey` 并反馈成功状态。
- 已绑定成员、待接受邀请和仍有效的未关联租客资料只要具有 `SeatSlot`，同一字段继续显示该按钮。Workspace 所有者行不显示租客资料或公开链接。
- “编辑租客信息”及创建待认领席位时共用“自助管理”字段：允许后续自助换号、允许导出数据、换号冷却天数。冷却默认 7 天，建议校验为 1 至 365 的整数；关闭换号时保留但禁用冷却输入。

### 首次认领

- `seatKey` 是首次认领的能力凭据，不另设首次认领开关；管理员发送 URL 即表示允许该席位被首次认领。
- 待认领页面使用“填写邮箱并接收邀请”，不是“换号”。成功创建 `default` 邀请后，原 `SeatSlot`、`seatKey`、租客资料和历史保持不变，状态转为邀请中。
- 首次认领成功时间同时作为下一次公开换号冷却的起点。失败请求、相同邮箱幂等请求和管理员操作不重置冷却。
- 已到期、已停用、缺少可管理执行账号、容量不再可用或已有活动自助操作时拒绝认领。

### 后续换号

- `allowSelfServiceSwap` 默认关闭；现有租客不回填开启，避免历史 URL 在上线后突然获得移除正式成员的权限。
- 只有开关开启、冷却已结束、席位活动且未到期时才允许后续换号。公开视图返回明确的禁止原因和下一次可换号时间，由后端而非浏览器决定最终权限。
- 待接受邀请的换号先撤销旧邀请，再邀请新邮箱；已接受成员的换号先移除旧成员，再邀请新邮箱。整个流程保留同一 `SeatSlot` 和 `seatKey`。
- 开启配置和公开提交页面都必须提示：旧成员立即失去 Workspace 访问，相关凭证可能失效，旧席位可能继续临时计费，新成员可能形成新增付费席位。
- 单个 `SeatSlot` 同时最多一个认领或换号操作。上游部分成功时保存每一步结果和可恢复状态，不用本地回滚伪装上游已经撤销。

### 数据导出

- `allowSelfServiceExport` 默认关闭；待认领席位没有当前邮箱和导出目标，即使开关已配置也不可导出。
- 上游管理员接口样本提供后，再确认导出目标、必要参数、同步下载或异步任务、结果保存边界、频率限制和失败恢复。
- 公开页面不得获得管理员接口凭证，也不得把 Session、Workspace Credential 或其他账号秘密当作“数据导出”返回。

## 数据与接口计划

| 范围 | 计划 |
|------|------|
| `seat_slots` | 支持 `unclaimed` 状态和空当前邮箱；新增后续换号开关、数据导出开关及默认 7 天的冷却配置，两个开关默认关闭 |
| 容量投影 | 保持 `fixedSeatOccupied` 的远端事实语义，新增待认领数量和本地可分配余量投影，不持久化容量空位 |
| 自助操作 | 区分首次 `claim`、后续 `swap` 和未来 `export`；冷却从最近一次成功认领或换号完成时间派生，不双写最后换号时间 |
| 管理 API | 创建待认领席位、更新自助配置、读取稳定 `seatKey`；必须使用活动 owner/admin 执行账号 |
| 公开 API | 按 `seatKey` 返回有效能力、禁止原因、冷却截止时间和操作历史；认领、换号、导出分别校验服务端策略 |
| 上游请求 | 继续通过具名 `Transport` 保存完整私有追踪；数据导出接口名称等待样本 |

## 安全与风险

- `seatKey` 是免登录能力凭据，应保持高熵并避免出现在普通日志；公开写接口需要按 IP 和 `seatKey` 限流。
- 容量预留和首次认领必须串行校验同一 Workspace 的最新容量、远端占用和待认领数量，避免并发超额预留。
- 已接受成员的自动换号是管理员逐席位授权的高风险动作；完整保存成员移除返回的 `billing_notice`、`policy_notice`、已知字段摘要和活动日志。
- 公开认领、换号和导出只允许活动且未到期的客户席位。过期或停用链接保留稳定错误页面，不得重新激活远端关系。
- 公开页面当前可见邮箱、联系方式、备注、价格和到期日；实施前需要再次确认哪些字段继续公开，以及是否增加重新生成 `seatKey` 的失效入口。

- 数据库集成测试覆盖容量未知、无余量、并发预留、待认领、首次邀请、冷却边界、过期、停用和单席位操作锁。

- Web 测试覆盖成员字段链接、待认领行、表单默认值、禁止原因、下一次可换号时间和深浅主题。
